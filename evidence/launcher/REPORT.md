## What was implemented

- **HOME activity** `org.ztmetro.start/.StartActivity`: `MAIN` + `HOME` + `DEFAULT`,
  `exported`, `launchMode=singleTask`, `clearTaskOnLaunch`, `excludeFromRecents`,
  `stateNotNeeded`, `enableOnBackInvokedCallback`. No permissions at all; package
  visibility comes from `<queries>` for `MAIN`/`LAUNCHER` (no `QUERY_ALL_PACKAGES`).
- **Edge-to-edge without hiding the status bar**: `setDecorFitsSystemWindows(false)` on
  API 30+ (or `LAYOUT_*` flags on 29), transparent status bar over the black canvas,
  white icons, top inset added to the header, bottom inset to the content. The system
  status bar and navigation bar remain visible and functional.
- **Metro page header**: caps subtitle from `type.header.subtitle_size_sp` (11.5 sp
  Semibold, `TextAppearance.Metro.Caps`) and 48 sp Semilight page title
  (`TextAppearance.Metro.PageTitle`), on the token page margin.
- **Pivot row "start | apps"**: selected title white, other `text_muted` (`#616161`),
  token pivot height / 48 dp minimum touch target, switching with the ztmetro
  slide/fade (`page_gap_ms` 120 → `page_ms` 300, decelerate) plus title cross-fade.
- **Start tile grid**: 6 columns at the 360 dp reference; unit computed at runtime with
  the C formula `unit = (width − 2·margin − (cols−1)·gutter) / cols` (49.5 dp at 360 dp),
  medium 2×2 (106 dp) and wide 4×2 (219 dp) tiles, accent fill (`#0050EF`), pressed fill
  `accent_light1`, app icon and label (`TextAppearance.Metro.Body`, system sans-serif).
  Row packing is 6-unit occupancy, tile rows scroll inside a ScrollView.
- **Tile long-press (450 ms token)** opens a bottom Metro sheet: open, medium/wide
  resize, unpin. **App-list long-press** offers pin as medium/wide tile (or unpin if
  already pinned). Sheet is a white panel with black rows, 0.72 scrim from tokens.
- **App list page**: alphabetical sections, 55 dp rows, 45 dp icon, 22 sp
  `app_list_title`, no dividers, ListView recycling, tap launches.
- **Store**: SharedPreferences JSON `[{pkg,cls,size}]`; seeded on first run from
  `PackageManager.queryIntentActivities(MAIN/LAUNCHER)` with the first 8 apps (pattern
  wide/medium/medium), labels re-resolved on every load, uninstalled tiles dropped.
- **Predictive back**: manifest opt-in + `OnBackInvokedCallback` (API 33+, isolated in a
  static inner class); apps → start page, back on start is consumed. API 29–32 uses the
  `onBackPressed` path. Launching apps uses `ACTION_MAIN` + `CATEGORY_LAUNCHER` + the
  exact `ComponentName`, with `NEW_TASK`/`RESET_TASK_IF_NEEDED`.

## Token pipeline (no hand-duplicated numbers)

`scripts/build-launcher.sh` runs `design/tokens/gen_android.py --out launcher/build/gen-tokens`
(which validates that every metric/motion/colour still has a provenance entry), then a
small Python step merges the generator's colours, dimens and TextAppearances into one
generated **`launcher/build/res/values/metro_tokens.xml`**, adding only what the launcher
needs and reading it from the same JSON: `type.header.gap` (10 dp), `chrome.scrim_alpha`
(72 %), and `TextAppearance.Metro.AppListTitle` / `BodyLarge` from the ramp. The file is
regenerated on every build and never edited by hand; a copy of the build actually used is
in `evidence/launcher/metro_tokens.generated.xml`.

Java reads the accent and the type ramp from these compiled resources: `R.color.metro_*`
and `MetroUi.text(context, R.style.TextAppearance_Metro_*)`, which resolves
`textSize`, `fontFamily` and `textColor` from the generated style. Families are the system
`sans-serif` / `sans-serif-light` / `sans-serif-medium`, so a system font module applies;
`Typeface.create` falls back to the default face if a family is missing.

## Build commands (exact)

On hermes-ubuntu, with the repo at `~/ztux/launcher`:

```sh
cd ~/ztux/launcher
./scripts/build-launcher.sh
```

The script is idempotent: it wipes generated resource/class/dex intermediates, keeps the
keystore so rebuilds keep the same signing identity, and prints APK path, size and sha256.
It is also byte-reproducible: the dex entry gets a fixed zip timestamp, so two consecutive
builds on the same host produce the identical sha256 (verified: 971297ef… repeated runs).
It discovers the SDK from `ANDROID_HOME` / `ANDROID_SDK_ROOT` / `~/android-sdk` and the
JDK from `JAVA_HOME` / `~/android-jdk`; it dies if `platforms/android-36/android.jar` is
missing. Toolchain used: `aapt2 compile --dir res` → `aapt2 link` → `javac -source 8
-target 8` → `d8 --release --min-api 29` → `zip` → `zipalign -f 4` → `apksigner sign`.
The APK is signed with v1 off and v2+v3 requested; at minSdk 29 apksigner emits the v3
block (v3 supersedes v2), then `apksigner verify` must pass before the script finishes.

## Expected screen on the 720×1280 / 320 dpi device (360×640 dp)

Black canvas, status bar visible with white icons. Top-left: small caps `ZTMETRO`
(11.5 sp Semibold), below it the 48 sp Semilight page title `start`. A tall pivot row
with `start` in white and `apps` in grey (`#616161`). Below, the Start grid fills the 360 dp
width: each six-unit row is either three 106 dp medium tiles or one 219 dp wide tile
plus a medium tile, in flat `#0050EF` cobalt with a white app icon top-left and up to
two white 13 sp label lines bottom-left; the grid scrolls. Tapping `apps` slides/fades to a black alphabetical list:
accent letter heads (`A`, `B`, …), 55 dp rows with 45 dp icons and 22 sp light app names,
no dividers. Tapping a tile or row starts that app; Home returns here (singleTask). Long
press a tile → white sheet from the bottom over 72 % black dim with `open`, `make wide`
(or `make medium`) and `unpin from start`; long press an app row → pin as medium/wide.

## adb install / default-home commands

```sh
# note the current stock home first, so reverting is exact
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN \
    -c android.intent.category.HOME
adb install -r evidence/launcher/ztmetro-start.apk

# make it the default HOME (no UI tap needed)
adb shell cmd package set-home-activity org.ztmetro.start/.StartActivity
adb shell cmd package resolve-activity --brief -a android.intent.action.MAIN \
    -c android.intent.category.HOME          # expect org.ztmetro.start/.StartActivity

# belt-and-braces: press Home / start the activity directly
adb shell input keyevent KEYCODE_HOME
adb shell am start -n org.ztmetro.start/.StartActivity -a android.intent.action.MAIN \
    -c android.intent.category.HOME

# memory check (budget: keep the launcher small; expected 20–40 MB PSS, unmeasured)
adb shell dumpsys meminfo org.ztmetro.start | head -20

# revert to the stock launcher (replace with the component noted above)
adb shell cmd package set-home-activity com.android.launcher3/.uioverrides.QuickstepLauncher
adb uninstall org.ztmetro.start
```

## Known limitations

- **No live tiles** (no notification listener; that is a later scenario step). Tiles are
  static app shortcuts; no unread counts.
- No drag-to-reorder, folders, resize handles/gesture, search on the apps page, or
  widgets. Resize/pin/unpin is via the long-press sheet only.
- Tiles are drawn on one canvas View: they are not individually focusable for
  TalkBack (the app list is a normal ListView and is accessible). Accessibility for the
  grid is a known gap.
- Predictive back is handled (manifest opt-in + `OnBackInvokedCallback`) but the
  in-app gesture is not driven by `OnBackAnimationCallback`: Android plays its default
  transition rather than a per-pixel page slide.
- The seeded set is the first eight installed launcher activities; a device with fewer
  apps seeds fewer tiles. Pinning an app appends it to the end of the grid.
- Wallpaper is intentionally the ztmetro black canvas, not a wallpaper image.
- The launcher only draws itself; the real status bar, shade, keyguard and nav bar are
  still SystemUI (see `docs/07-ztmetro-mapping.md`).
- Signing key is throwaway and gitignored; rebuilds are signed by the same key only on
  the same host/path. A fresh clone generates a new identity (never shipped to a store).
- No runtime measurement yet: first install, first-run seed, font-scale changes and
  rotation must be checked on the device before RAM/PSI acceptance.
