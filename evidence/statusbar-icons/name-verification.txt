## 4. Battery / wifi / signal are NOT SystemUI drawables (not shipped)

# stat_sys_battery*: no file in packages/SystemUI/res/drawable*/ (grep of the whole
#   SystemUI res tree finds only stat_sys_data_bluetooth_connected_battery_*).
#   The only stat_sys_battery* assets in the tree are framework leftovers:
#   core/res/res/drawable-*/stat_sys_battery_{0,10,15,20,28,40,43,57,60,71,80,85,100}.png
#   plus charge anims, referenced by core/res/res/values/symbols.xml:2151-2153.
#   SystemUI 23.2 draws the battery in code:
#   packages/SystemUI/src/com/android/systemui/battery/BatteryMeterView.java:77,123
#   packages/SystemUI/src/com/android/systemui/battery/AccessorizedBatteryDrawable.kt:49
#       : DrawableWrapper(ThemedBatteryDrawable(context, frameColor))
#   new path: pipeline/battery/shared/ui/BatteryFrame.kt (Compose Canvas).
#
# wifi: WifiIcon.Visible carries a resource id, but the array is either framework
#   or SettingsLib — never a SystemUI drawable:
#   packages/SystemUI/src/com/android/systemui/statusbar/connectivity/WifiIcons.java:34-53
#       com.android.internal.R.drawable.ic_wifi_signal_0..4      (flag off)
#       com.android.settingslib.R.drawable.ic_wifi_0..3          (new_status_bar_icons on)
#   There is no stat_sys_wifi_signal_* anywhere in the 23.2 tree.
#
# signal: five bars drawn by SettingsLib's SignalDrawable (Canvas), used from
#   packages/SystemUI/src/com/android/systemui/statusbar/connectivity/MobileSignalController.java:234-248
#   and, on the new path, by Compose MobileSignalIcon
#   (pipeline/mobile/ui/compose/MobileIcon.kt:183).
#   There is no stat_sys_signal_* drawable in SystemUI; the framework has only
#   leftover cdma/evdo PNGs (core/res/res/drawable-*/stat_sys_signal_*_cdma.png).

# SAB chip/background: no chip background sits behind the status-icon row in
