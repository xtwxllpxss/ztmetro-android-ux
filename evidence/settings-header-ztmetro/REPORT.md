## 2. Exact view-tree mutations and their guards

All mutations are on the **host** tree from `android.R.id.content`/window decor; nothing is
compiled against Settings classes, all ids are resolved by name at runtime, and every step
is `try/catch(Throwable)` (a failure logs and leaves Settings stock). The module only
decorates screens that carry the `ztmetro_header` tag: dialogs and helper
`FragmentActivity`s in the Settings process are skipped in `HeaderBinder.refresh`.

| # | view / target | mutation | guard |
|---|---|---|---|
| 1 | `content_frame` (`SettingsBaseActivity` screens, incl. `SubSettings`) | insert header at **index 0**, `MATCH_PARENT × WRAP_CONTENT`; every other child gets `topMargin = header.getHeight()` (initial 104 dp, corrected after layout) | container found by id; old `ztmetro_header` removed first (idempotent); header **never** inserted into `settings_main_prefs`, so `main_content`'s `layout_weight=1` is untouched; header is a sibling of the screen layout, not of the fragment |
| 2 | `homepage_container` (`SettingsHomepageActivity`) | insert header at **index 0** of the vertical LinearLayout (scrolls with the page); status-bar height added to its top padding; container's `-8dp` top margin compensated on the header | same id check; homepage detected by activity class name (not by a hard-coded Settings id chain) |
| 3 | stock top chrome: `action_bar`, `app_bar`, `app_bar_container`, `search_action_bar` | set `GONE` (home: app bar/search bar; base: toolbar/app bar) | **skip if the view is an ancestor of the content host**; if `primary_button` / `secondary_button` / `action_button` is `VISIBLE` (Save/Done flow), the toolbar is **kept**, painted black, title cleared; `clearStockToolbarTitle()` reflective and best-effort |
| 4 | header title/subtitle | re-bind on attach, `setTitle(CharSequence)` and `onResume`; title = `Activity.getTitle()` lowercased, tokens that are already ALL-CAPS stay; subtitle = last back-stack breadcrumb that differs from the title (case-insensitive), else `@string/metro_header_subtitle_static` = `ztMetro` | androidx breadcrumb access purely reflective; any missing method only costs the subtitle |
| 5 | dashboard row icons | `ImageView#setVisibility(GONE)` on the home page only; log `hid N dashboard row icons` | only inside `main_content` (fallback `homepage_container`) → its RecyclerView; skips ids/classes with `arrow`, `chevron`, `expand`, `collapse`, `more`, `overflow`, `button`, `toggle`, `switch`, `search`, `check`, `radio`; skips any icon inside a switch/CompoundButton; skips standalone clickable icons with a content description; requires an ancestor within 3 levels that passes the preference-row test **and** keeps a text title |
| 6 | preference rows (all screens) | `setBackgroundColor(0xFF000000)`, `setElevation(0)`, start/end padding = 24 dp, margins zeroed when they are card insets (≤24 dp horizontal, ≤16 dp vertical); the title and its inner containers get their **start inset cleared** (≤96 dp) so removing the icon does not leave a ~60 dp hole; log `flat rows: N preference rows flattened` | row = short `ViewGroup` (≤220 dp) with ≤8 children containing `@android:id/title` within 3 levels; **protected ids** never touched: `content`, `content_parent`, `content_frame`, `main_content`, `main_content_scrollable_container`, `homepage_container`, `settings_homepage_container`, `suggestion_content`, `contextual_cards_content`, `switch_bar`, `button_bar`, `app_bar*`, `action_bar`, `collapsing_toolbar`, `search_action_bar`, `search_bar_title`; protected classes: `*RecyclerView*`, `*ScrollView*`, `*CoordinatorLayout*`, `*Toolbar*`, `*ViewPager*`, `*TabLayout*`, `*FragmentContainer*`; a detected row's children are not re-walked |
| 7 | bottom bar (all decorated screens) | add `metro_bottom_bar` (40 dp, `MATCH_PARENT`, `Gravity.BOTTOM`, tag) **last** to the window decor; `content.setPaddingBottom ≥ 40 dp + nav-bar inset` (never accumulates; a larger Settings/IME inset is preserved) | decor must be a `FrameLayout`; idempotent by tag; back: `getOnBackPressedDispatcher().onBackPressed()` reflectively → `Activity.onBackPressed()` → `finish()`; search: `Intent("android.settings.SETTINGS")` + boolean extra `search`, `resolveActivity` guard, otherwise logged no-op |
| 8 | window chrome | status/navigation bar colours black (best effort), decor and `android.R.id.content` backgrounds black | all calls guarded; Android 15+ may ignore the colour setters on edge-to-edge windows |
| 9 | re-apply passes | immediate + 200/700/1600 ms, coalesced per `Activity`, a new kick cancels the previous chain | only for activities with our header; no permanent poller; main thread only |

## 3. Expected before/after

**Settings home** (launcher entry or fallback home):

- *before*: cobalt 56 dp banner (“Настройки / ztMetro”), search app bar, grey rounded cards
  each with a blue circled icon and a chevron, Material top bar.
- *after*: black screen from the status strip down; `SETTINGS` caps label, large light
  lowercase title (`settings`), small 70 % subtitle (`ztMetro`); flat black rows with text
  and chevrons only (no icons); no app bar; 40 dp bottom bar with back / `ZRN` / search;
  the last row is not covered (40 dp + nav inset padding).

**Wi-Fi** (and any `SubSettings` screen):

- *before*: Material toolbar with the screen title and back arrow; card-grouped rows with
  icons; no bottom chrome.
- *after*: toolbar/AppBar hidden; header block `SETTINGS` / `wi-fi` (as Settings provides
  it, lowercased) / breadcrumb-or-`ztMetro` subtitle; flat black preference rows with
  24 dp page margin; switches keep their cobalt tint (`MetroTinter`); bottom bar present,
  back works through the activity back dispatcher. Screens that show a Save/Done action
  keep a black toolbar so the flow still works.

Titles are one line (`maxLines=1`, ellipsize end) at 48 sp, so long stock titles
("Network & internet") are ellipsized rather than shrunk — documented as deferred polish.

Context: the lead's device session captured the target chrome in
`evidence/ux-compare/current/e0-settings.png` (12:19, `cmp-settings-3way-v2.png` middle
panel) — black page block, caps label, lowercase Cyrillic title, icon-free flat rows and
the bottom bar.  That capture is **not** this build; it still shows the stock text inset
left over from the hidden icon, which change 6 in this module now also clears (title moves
to the 24 dp page margin).  No device capture of this exact APK exists yet.

## 4. Install (lead, with the device)

The debug key is created per build directory, and this build is **v3-signed only**, so
replace the previous module installation rather than updating it:

```sh
adb uninstall org.ztmetro.settingsheader
adb install repo/evidence/settings-header-ztmetro/ztmetro-settings-header.apk
# LSPosed: module "ztMetro Settings" → enable, scope must contain com.android.settings
adb shell am force-stop com.android.settings      # LSPosed injects on the next process start
```

If the old module was already enabled, uninstalling removes it from LSPosed's list: open
LSPosed after the install, enable **ztMetro Settings** and tick only `com.android.settings`
in its scope, then open Settings again.

## 5. LSPosed scope

`com.android.settings` only (declared in `res/values/arrays.xml` → `xposedscope`;
`assets/xposed_init` → `org.ztmetro.settingsheader.ModuleEntry`; `xposedminversion 93`).
Nothing in this module runs in SystemUI or the launcher.

## 6. Implemented vs deferred

Implemented (all five requested changes): flat black 104 dp header with caps label /
48 sp light lowercase title / 12 sp subtitle; hidden dashboard row icons with a
conservative row/chevron guard and a count log; flat black preference rows with card
background/elevation/margins removed and 24 dp page margin (fragment container never
touched); 40 dp back / `ZRN` / search bottom bar with content padding so the last row is
never covered; build + `aapt2 dump badging` + `dexdump` verification with the APK sha256.

Deferred / not in this cut:

- **Rectangular toggle**: switches remain Material switches (cobalt-tinted by
  `MetroTinter`); a true square track needs a replacement state-list drawable for the
  host switch class, not reachable from module resources — deferred.
- **Divider lines** between rows: the reference has nearly none; none added.
- **Long-title autosize**: one line at 48 sp per the requested spec; ellipsis on long
  titles is accepted for now.
- **Per-item icon stripping on sub-screens**: deliberately limited to the home dashboard
  (Wi-Fi rows may still show their stock icons, flattened but not icon-free).
- **Dashboard items without `@android:id/title`** are not flattened (conservative guard) —
  if the device shows a card that survives, the ids to inspect are in the log line
  `flat rows: N preference rows flattened`.
- **Device acceptance** (screenshots, scroll-to-last-row, back/search taps): not executed
  here; no adb by instruction. The static evidence proves packaging/resource/dex content,
  not on-device rendering.
- **Dedicated Settings search UI**: the search glyph starts stock Settings with
  `android.settings.SETTINGS` + `search` extra (documented no-op if the intent does not
  resolve), as specified; it is not a new search screen.
